# 라인스캔 검사장비 — 1축 엔코더 트리거 하드웨어 설계서

| 항목 | 내용 |
|---|---|
| 대상 | 신규 라인스캔 검사장비 (1축 스캔) |
| 서보 드라이버 | Panasonic **MBDLT25SM** 200 V (MINAS A6S 계열, 400W, **펄스입력형**) |
| 이송 기구 | 리니어모터 + 리니어스케일 (full-closed) |
| 축 제어 | **Ajinextek 모션 보드 (펄스 출력)** — AXL 통합 |
| 트리거 모듈 | Ajinextek **SIO-HPC4L** (엔코더 4CH, 차동 입력 ~5 MHz) |
| 트리거 피치 | **5.0 µm** |
| 트리거 출력 | 5 V TTL (push-pull) → 카메라 Trigger IN |

> **개정 이력**
> - Rev.1 : 초안 (FASTECH Ez-ML 유지, 드라이버 계열 미확정)
> - **Rev.2 : 실물 확인 반영. FASTECH Ez-ML-PE-PAN 제거, X4를 아진 커넥터로 직결하는 구성으로 전면 변경**

## 1. 구성 변경의 배경

### 실물 확인 결과

현장 사진으로 다음이 확인되었습니다.

| 항목 | 확인 내용 |
|---|---|
| 드라이버 라벨 | **MBDLT25SM 200 V** |
| 네트워크 모듈 | **FASTECH Ez-ML-PE-PAN** (Ezi-MotionLink **Plus-E**), S/N 230306572 |
| 모듈 I/F | Ethernet-IN / OUT 데이지체인, 로터리 노드주소 스위치 2개, 표시 "02" |
| 드라이버 커넥터 | X1(mini USB), X2, X3, X5 육안 확인 |

**핵심 발견: 이더넷은 드라이버가 아니라 FASTECH 애드온 모듈이 제공하고 있었습니다.**
MBDLT25SM 자체는 모델코드의 `S`가 가리키는 대로 **평범한 A6S 펄스입력형 드라이버**입니다. Ezi-MotionLink Plus-E는 Panasonic MINAS(A/A3/A4/A5/A6)의 지령 I/O 커넥터에 플러그인되어 펄스 지령을 만들어 주는 네트워크 모션 컨트롤러입니다.

### 결정

**Ez-ML 모듈을 제거하고 X4를 아진 커넥터로 직결한다.**

이로써 초안의 두 가지 미결 리스크가 동시에 해소됩니다.
- 드라이버 계열 불명 → A6S 펄스형으로 확정, 분주 출력 보유 가능성 높음
- X4 커넥터 경합 → 모듈 제거로 소멸

## 2. 시스템 구성

```
 ┌─ PC : SEQApp + AXL ─────────────────────────────────┐
 │                                                      │
 │  [아진 모션 보드]                                     │
 │     PULS± / SIGN±  ──────────────┐                   │
 │     SRV-ON, A-CLR, CL ───────────┤                   │
 │     ALM, S-RDY, INP  ◀───────────┤                   │
 │                                  │                   │
 │  [아진 SIO-HPC4L]                │                   │
 │     ENC A±/B±/Z±     ◀───────────┤                   │
 │     TRIG OUT ────────────────────┼──▶ [라인스캔 카메라]│
 │                                  │      pin1 Trigger IN│
 │  [아진 DIO]                      │                   │
 │     리밋 / 원점 / EMG ───────────┤                   │
 └──────────────────────────────────┼───────────────────┘
                                    │ X4 (50pin)
                          ┌─────────▼─────────┐
                          │   MBDLT25SM       │
                          │   MINAS A6S 400W  │
                          └───┬───────────┬───┘
                          X5  │           │ U/V/W
              [리니어스케일]──┘           └──▶ [리니어모터]
                 (full-closed 피드백)
```

### 이 구성의 이점

| 항목 | 효과 |
|---|---|
| 소프트웨어 | **SEQApp 기존 AXL 코드 재사용.** FASTECH 라이브러리 통합 불필요 |
| 커넥터 | X4 경합 없음 — 지령·상태·분주출력을 한 커넥터에서 |
| 벤더 | 모션·트리거·DIO 모두 아진 = AXM / AXC / AXD 단일 라이브러리 |
| 동기 | 지령과 트리거가 같은 PC·같은 라이브러리 → 스캔 시퀀스 일원화 |

## 3. ★ 핵심 개념 — 지령 분해능과 트리거 분해능은 **독립**입니다

설계에서 가장 혼동하기 쉬운 지점입니다.

| | 지령 펄스 (아진 → 드라이버) | 분주 출력 (드라이버 → HPC4L) |
|---|---|---|
| 방향 | 아진 → 드라이버 | 드라이버 → 아진 |
| 의미 | "이만큼 가라" (목표) | "이만큼 갔다" (실제) |
| 분해능 결정 | 전자기어 Pr0.08~0.10 | 분주 설정 (Pr0.11 계열) |
| 필요 정밀도 | **낮아도 됨** — 서보가 보간 | **높아야 함** — 트리거 위치 정확도 |
| 권장값 | P_cmd = 0.5 ~ 1.0 µm | UPP = 0.1 µm |

**트리거는 반드시 분주 출력(실제 위치)에서 뽑습니다.** 지령 펄스에서 트리거를 만들면 추종오차·정정거동이 반영되지 않아 무의미합니다.

## 4. 수치 설계

### 4.1 제약 조건

| # | 제약 | 값 |
|---|---|---|
| C-1 | 트리거 피치가 **정수 엔코더 카운트** | `5.0 µm / UPP = 정수` |
| C-2 | 드라이버 분주 출력 상한 | **4 Mpps** |
| C-3 | HPC4L 차동 입력 상한 | **5 MHz** |
| C-4 | 드라이버 지령 펄스 입력 상한 | **4 Mpps** (라인드라이버) |
| C-5 | 아진 모션 보드 펄스 출력 상한 | 보드별 — **확인 필요** |

### 4.2 트리거측 — UPP 후보

`UPP` = 4체배 후 1카운트 거리 · `f_A` = 분주 출력 A상 주파수 = `v / (4 × UPP)`

| UPP | 5 µm의 카운트 | 피치 조정 스텝 | f_A @300 mm/s | @500 mm/s | @800 mm/s |
|---|---|---|---|---|---|
| 0.5 µm | 10 | 10 % | 150 kHz | 250 kHz | 400 kHz |
| 0.25 µm | 20 | 5 % | 300 kHz | 500 kHz | 800 kHz |
| **0.1 µm** | **50** | **2 %** | 750 kHz | **1.25 MHz** | 2.0 MHz |
| 0.05 µm | 100 | 1 % | 1.5 MHz | 2.5 MHz | 4.0 MHz ⚠ |
| 0.025 µm | 200 | 0.5 % | 3.0 MHz | 5.0 MHz ❌ | ❌ |

**권장: UPP = 0.1 µm** (피치 = 정확히 50 카운트, 500 mm/s에서 4 Mpps 대비 여유 3.2배)

치수 측정을 병행하면 UPP 0.025 µm(ε 0.5 %)로 올리되 **최고속이 300 mm/s로 제한**됩니다.

### 4.3 지령측 — P_cmd 후보

`f_cmd = v / P_cmd`

| P_cmd | f_cmd @300 mm/s | @500 mm/s | @800 mm/s | 판정 |
|---|---|---|---|---|
| 0.1 µm | 3.0 Mpps | 5.0 Mpps ❌ | ❌ | 과도 |
| 0.2 µm | 1.5 Mpps | 2.5 Mpps | 4.0 Mpps ⚠ | 가능 |
| **0.5 µm** | 0.6 Mpps | **1.0 Mpps** | 1.6 Mpps | **권장** |
| 1.0 µm | 0.3 Mpps | 0.5 Mpps | 0.8 Mpps | 여유 |

**권장: P_cmd = 0.5 µm.** 등속 스캔이므로 지령이 거칠어도 서보가 매끄럽게 추종합니다. 아진 보드 출력 상한(C-5)에도 여유가 큽니다.

### 4.4 라인스캔은 TDI보다 관대합니다

| | TDI 256단 (기존 장비) | 라인스캔 (신규) |
|---|---|---|
| 피치 오차 ε의 영향 | **smear = 256 × ε** | 이미지 종횡비 오차 = ε |
| ε = 1 % 일 때 | 2.56 px 뭉갬 | 100 px당 1 px 신축 |
| 허용 ε | 0.2 % | **0.5 ~ 2 %** (용도별) |

- 외관 검사만 → ε 2 % 이내 실용상 무해 → UPP 0.1 µm로 충분
- 치수 측정 병행 → ε 0.5 % 이내 → UPP 0.025 µm + 속도 제한

### 4.5 속도 상한

```
v_max = 카메라 라인레이트 × 5.0 µm
```

| 라인레이트 | v_max | UPP 0.1 µm의 f_A | P_cmd 0.5 µm의 f_cmd |
|---|---|---|---|
| 50 kHz | 250 mm/s | 625 kHz ✅ | 500 kpps ✅ |
| 100 kHz | 500 mm/s | 1.25 MHz ✅ | 1.0 Mpps ✅ |
| 150 kHz | 750 mm/s | 1.88 MHz ✅ | 1.5 Mpps ✅ |
| 200 kHz | 1,000 mm/s | 2.5 MHz ✅ | 2.0 Mpps ✅ |

권장 조합(UPP 0.1 µm / P_cmd 0.5 µm)은 카메라 200 kHz까지 모든 제약을 만족합니다.

> 오버트리거(트리거가 카메라 라인주기보다 빨리 도착)는 라인 누락 → 이미지 압축으로 나타납니다. **v_max에 20~30 % 마진**을 두십시오.

## 5. X4 신호 분배

X4 50핀을 세 계통으로 나누어 아진 보드에 배분합니다.

### 5.1 지령·제어 (아진 모션 보드 → 드라이버)

| 신호 | 내용 | 방향 |
|---|---|---|
| PULS1 / PULS2 | 지령 펄스 (라인드라이버 권장) | 아진 → 드라이버 |
| SIGN1 / SIGN2 | 지령 방향 | 아진 → 드라이버 |
| SRV-ON | 서보 ON | 아진 → 드라이버 |
| A-CLR | 알람 클리어 | 아진 → 드라이버 |
| CL | 편차카운터 클리어 | 아진 → 드라이버 |
| POT / NOT | 정/역 오버트래블 | 아진 → 드라이버 |
| COM+ / COM− | I/O 24 V 전원 | — |

### 5.2 상태 (드라이버 → 아진 모션 보드 / DIO)

| 신호 | 내용 |
|---|---|
| ALM+ / ALM− | 서보 알람 |
| S-RDY+ / S-RDY− | 서보 레디 |
| INP+ / INP− | 위치결정 완료 |
| BRK-OFF+ / BRK-OFF− | 브레이크 해제 (리니어모터는 해당 시) |

### 5.3 분주 출력 (드라이버 → SIO-HPC4L) ★

| 신호 | HPC4L |
|---|---|
| OA+ / OA− | ENC A+ / A− |
| OB+ / OB− | ENC B+ / B− |
| OZ+ / OZ− | ENC Z+ / Z− |
| SG (신호 GND) | GND |

- **실드 트위스트 페어 3쌍**, 실드는 드라이버측 1점 접지
- 차동 전송이므로 노이즈 내성 양호. 서보 전력선과 분리 배선
- Z상은 원점 복귀용 (스캔 트리거에는 미사용이나 원점 재현성 확보에 유리)

> ⚠️ **X4 핀 번호는 본 문서에 기재하지 않았습니다.** 검색으로 원문 대조를 하지 못했고, 오결선 시 손상 위험이 있어 **해당 모델 매뉴얼의 X4 핀 배치도로 직접 확인**하십시오. 신호 이름은 MINAS A5/A6 공통 명칭입니다.

### 5.4 트리거 출력 (SIO-HPC4L → 카메라)

| HPC4L | 카메라 Control I/O |
|---|---|
| TRIG OUT 0 | pin 1 — Trigger IN |
| GND | pin 3 — DC GND |

- 5 V TTL push-pull ↔ 카메라 V_IH 2~5 V → **레벨 호환, 풀업 불필요**
- **케이블 1 m 초과 시 출력단에 직렬 33~47 Ω** (반사·링잉 억제). 링잉이 입력 임계값을 넘나들면 1펄스가 2펄스로 계수됩니다
- 실드 트위스트 페어, 2 m 이내 권장
- 접지 전위차 우려 시 **고속 포토커플러(6N137급, ~10 Mbps)** 절연. 일반 포토커플러는 응답 부족으로 사용 불가
- 카메라측 핀 배열도 매뉴얼 대조 필요

## 6. 아진 보드 요구 사양

| 기능 | 요구사항 |
|---|---|
| 모션 1축 펄스 출력 | 라인드라이버 출력, **≥2 Mpps** (P_cmd 0.5 µm · 1,000 mm/s 기준), `AxmMotSetPulseOutMethod` 지원 |
| 엔코더 트리거 | **SIO-HPC4L** — 차동 입력 5 MHz, periodic 모드 위치주기 트리거 |
| DIO | 서보 ON/알람/리밋/원점/EMG |

AXL 단일 라이브러리로 통합 제어합니다.

| 계열 | 담당 |
|---|---|
| **AXM** | 축 지령 (`AxmMotSetPulseOutMethod`, `AxmSignalSetServoOnLevel`, 프로파일 이동) |
| **AXC** | 트리거 (`AxcTriggerSetFunction` periodic mode) |
| **AXD / AXA** | DIO |

### 펄스 출력 방식

`AxmMotSetPulseOutMethod(lAxisNo, uMethod)`

| uMethod | 방식 |
|---|---|
| 0~3 | 1-pulse (PULSE + DIR) — Panasonic 표준, **권장** |
| 4~7 | 2-pulse (CW / CCW) |
| 8~9 | 2-phase (A/B 90°) |

드라이버측 지령 펄스 입력 형식(Pr0.05~0.07)과 일치시켜야 합니다.

## 7. 서보 파라미터

| 파라미터 | 설정 | 목적 |
|---|---|---|
| 제어 모드 | 위치 제어 (펄스 지령) | 아진 펄스 지령 수신 |
| 피드백 | full-closed (리니어) + X5 외부 스케일 | 리니어모터 위치 제어 |
| Pr0.05~0.07 | 지령 펄스 입력 형식 | 아진 출력 방식과 일치 |
| Pr0.08~0.10 | 전자기어 | **P_cmd = 0.5 µm** 가 되도록 |
| 분주 출력 소스 | **external scale** | X4 출력이 스케일 위치를 반영 ★ |
| Pr0.11 | 분주 출력 펄스 수 | **UPP = 0.1 µm** 가 되도록 |
| Pr0.12 | 출력 방향 반전 | 스캔 방향에 맞춰 (HPC4L `AxcSignalSetEncReverse`로도 대응 가능) |

> **Pr0.11은 "모터 1회전당 출력 펄스 수"로 정의된 회전형 기준 파라미터입니다.** 리니어모터/full-closed 구성에서 분주비가 어떤 파라미터로 결정되는지는 해당 모델 매뉴얼에서 확인해야 합니다. 스케일 펄스를 무분주로 그대로 출력할 수 있다면 양자화 오차가 없어 가장 유리하므로 우선 검토하십시오.

### 스캔 프로파일

```
가속 → 속도 정정(settling) → [트리거 구간 진입] → 등속 스캔 → [구간 이탈] → 감속
```

트리거 Block 구간을 등속 구간 안쪽으로 설정하고, 진입 전 정정이 끝나도록 조주 거리를 확보하십시오.

## 8. SIO-HPC4L 설정 (periodic mode)

버퍼를 사용하지 않는 하드웨어 위치주기 트리거입니다. **트리거 개수 제한이 없습니다.**

```cpp
AxcTriggerSetEnable       (ch, 0);          // 설정 중 출력 정지
AxcTriggerSetEncoderInput (ch, encInput);   // 엔코더 입력 0~3
AxcSignalSetEncInputMethod(ch, 0x03);       // A/B상 4체배
AxcSignalSetEncSource     (ch, 0x00);       // A/B상 신호
AxcSignalSetEncReverse    (ch, bReverse);   // 진행 방향

AxcMotSetMoveUnitPerPulse (ch, 0.0001);     // UPP = 0.1 um = 0.0001 mm
AxcTriggerSetFunction     (ch, 0x03);       // ★ periodic mode (위치 주기)
AxcTriggerSetBlock        (ch, start, end, 0.005);  // 구간 + 피치 5 um
AxcTriggerSetDirectionCheck(ch, 0x01);      // 증가 방향에서만

AxcTriggerSetTriggerOutport (ch, 0x1);      // Trigger Out 0
AxcTriggerSetTime           (ch, 2.0);      // 펄스 폭 2 us (카메라 최소 1 us)
AxcTriggerSetLevel          (ch, 1);        // High active
AxcTriggerSetTriggerOutCount(ch, 1);        // 주기당 1발

AxcTriggerSetTriggerCountClear(ch);
AxcTriggerSetEnable           (ch, 1);      // 활성화
```

- 스캔 원점: `AxcStatusSetActPos(ch, 0.0)`
- 정지: `AxcTriggerSetEnable(ch, 0)`

카메라측: `Trigger Mode` = On · `Trigger Source` = External · `Trigger Activation` = **Rising Edge**
(High active + push-pull이므로 논리 반전 없음)

> periodic mode(0x03)와 `SetBlock`/`SetPosPeriod`는 AXC 헤더에 SIO-HPC4 전용으로 명시되어 확실합니다.
> `AxcTriggerSetTriggerOutCount` / `AxcTriggerReadTriggerCount`는 헤더상 SIO-HPC4 명시가 없어 **지원 여부 확인 필요**.

### 주의 — SIO-HPC4에는 등간격 거리 트리거 모드가 없습니다

`AxcTableTriggerDistancePatternShot` / `AxcTriggerDistancePatternShot`(= `CCGC_CNT_DISTANCE_PERIODIC_TRIGGER`)은 **CNT_RECAT_SC_10 전용**입니다. SIO-HPC4의 트리거 모드는 RANGE(0) / VECTOR(1) / PATTERN(3) 뿐이며, PATTERN은 **주파수 기반 타이머**라 위치 동기가 아닙니다. 반드시 위 periodic mode를 사용하십시오.

## 9. 리스크 — Ez-ML 제거로 잃는 것

### R-1. 리니어모터 자극 검출 (magnetic pole detection) — **최우선**

리니어모터는 전원 투입 후 **자극(magnetic pole) 위치를 알아야 통전할 수 있습니다.**

- 절대치 스케일 + 자극위치 저장 구성이면 자동 복원
- 증분 스케일이면 **매 전원투입마다 자극검출 동작**이 필요

**Ez-ML 모듈이 이 시퀀스를 대행하고 있었다면, 모듈 제거 후 드라이버 자체 기능 + 아진 시퀀스로 재구현해야 합니다.**

→ Panasonic A6 리니어 모드의 자극검출 파라미터·시퀀스를 확인하고, 필요 시 SEQApp 초기화 루틴에 반영하십시오. **모듈 제거 전에 반드시 확인할 항목입니다.**

### R-2. Ez-ML의 궤적 생성·네트워크 기능 상실

1축 등속 스캔이므로 아진 보드의 프로파일 생성으로 충분합니다. **실질 영향 없음.**

### R-3. 다른 축이 Ez-ML 네트워크에 물려 있는 경우

사진의 Ethernet-OUT과 노드주소 "02"는 **데이지체인에 다른 노드가 존재할 가능성**을 시사합니다. 이 축만 분리할 때 나머지 노드의 통신이 끊기지 않는지 확인이 필요합니다.

### R-4. X4 배선 재작업

Ez-ML 전용 하네스를 아진 보드용 하네스로 교체해야 합니다. 신호 수가 많으므로(지령 4 + 제어 5 + 상태 8 + 분주 7) **50핀 커넥터 압착 하네스를 제작**하는 편이 확실합니다.

## 10. 검증 절차

| # | 항목 | 방법 | 판정 |
|---|---|---|---|
| V-1 | 분주 출력 확인 | X4 OA/OB를 스코프 차동 프로브로 관측, 알려진 거리 D 이동 후 펄스 계수 | `D / 펄스수` = 설계 UPP |
| V-2 | 카운터 검증 | `AxcStatusSetActPos(ch,0)` → 100 mm 이동 → `AxcStatusGetActPos` | 100.000 mm |
| V-3 | **트리거 개수** ★ | `AxcTriggerSetTriggerCountClear` → 200 mm 스캔 → `AxcTriggerReadTriggerCount` | **40,000** (200mm/5µm) |
| V-4 | 트리거 인식 | HPC4L 출력 + 카메라 **Strobe OUT(pin4)** 2채널 동시 관측, 속도 단계 상승 | 최고속까지 누락·중복 없음 |
| V-5 | 지령 추종 | 등속 구간에서 지령 위치 vs 실제 위치 편차 모니터 | 편차 안정 |
| V-6 | 이미지 검증 | 격자 타깃 스캔 → 스캔방향/어레이방향 치수비 | 종횡비 오차 = ε |

**V-3이 핵심입니다.** 실제 피치 = 이동거리 / 트리거수 이고, 설계값과의 차이가 곧 ε입니다. 이미지 촬상보다 빠르고 정량적입니다.
(API 미지원 시 카메라 Strobe OUT 또는 HPC4L 출력선을 카운터로 계수)

## 부록. 기존 TDI 장비 대비 개선점

기존 VT-16K5X-H140A-256 장비의 블러 원인 조사에서 확인된 사항을 신규 설계에 반영했습니다.

| 기존 문제 | 신규 설계 대응 |
|---|---|
| 위치 동기 트리거 경로 미구현 (`CAjinTrigger` 미인스턴스화) | periodic mode 하드웨어 트리거 경로 명시 |
| 소프트웨어 `Sleep(100)` 토글 트리거 | HW 위치주기 비교기 — 소프트웨어 개입 없음 |
| `StartTrigger()` 최대 10발 (버퍼 오버플로 존재) | 버퍼 미사용 — 트리거 개수 무제한 |
| 피치 양자화 미검토 | UPP를 피치의 정수 약수로 설계 단계에서 확정 |
| 트리거 펄스 폭 미확인 | 2 µs 명시 (카메라 최소 1 µs) |
| 엔코더 전송 노이즈 내성 | 차동(HPC4L) 채택 |
| 지령/피드백 경로 혼재 | 지령(AXM)과 트리거(AXC) 역할 명확 분리 |
